# 官方 Notebook 静态审计（声明 A18）

对象：`reference/EBBA.ipynb`（源自 <https://github.com/ifen1/EBBA>），共 22 个代码单元。
方法：`src/ebba/claims/audit.py::a18_official_notebook` 只解析 JSON 并做字符串/结构检查，
**不执行**任何 Notebook 代码（其依赖 PaddlePaddle，且不在本容器内）。

判定：**CONTRADICTED** —— 8 项协议检查中 7 项与论文描述不一致。

| # | 检查项 | 论文描述 | 官方 Notebook | 结果 |
|---|---|---|---|---|
| 1 | 图像池任务无关性 | 互联网/任务无关图像 | 直接使用 GTSRB `Final_Validation` 验证集 | ✗ |
| 2 | 每伪标签均衡 | 每类保留 N 张 | 未找到均衡代码 | ✗ |
| 3 | 样本量 | 未固定小样本量 | 11 批 × 64 = 704 张 | ✗ |
| 4 | 损坏数量 | 80 种（附录描述） | 15 类 × 4 强度 + 4 种除法 = 64 | ✗ |
| 5 | 除法损坏 | 除以大于 1 的正整数 | 循环从 `j=1` 开始，含恒等变换 | ✗ |
| 6 | TE 截断一致性 | Eq. 9-10 单一定义 | 两个函数用 `transfer > 5`，另一处用 `transfer > 4` | ✗ |
| 7 | t-SNE + Birch 聚类 | 区分目标类干净图与中毒图 | 无聚类步骤 | ✗ |
| 8 | BA / ASR 评估 | Table 3/4 的核心指标 | 对干净验证集与打补丁验证集分别推理，可换算 BA/ASR | ✓ |

## 解释

- 第 8 项通过，说明 Notebook 的**评估部分**与论文指标口径一致；它缺的是检测与去除流程
  （聚类、PDR/F1），以及论文协议要求的“任务无关、每类均衡”图像池。
- 第 3、4 项的偏差使该 Notebook 无法支撑正文“80 种损坏”“每类 N 张”的描述；
  但 704 张、64 种损坏本身能跑通，说明方法对小样本/少损坏有容忍度——这与论文的
  核心卖点方向一致，可作为流程参考。
- 官方 README 明确写道 CIFAR-10 上使用 `NP_k = P_k - 1`，与论文 Eq. 5 不同（→ A03）。
  这提示论文公式与实验代码之间存在未在正文披露的实现差异。

## 本项目如何处理

- 不执行官方 Notebook，不把它当作 Table 3/4 的可复现实现。
- 用 `src/ebba/energy.py` 同时实现论文 Eq. 5、官方 README 的 `P-1`、官方 Notebook 的
  `exp(2s)/2` 截断三种变体，在 A03 与 B03 中比较其对检测结论的影响。
- A18 的判定只反映“官方代码 ≠ 论文协议”，不构成对方法有效性的否定。
